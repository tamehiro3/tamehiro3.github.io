# あなたの作業の手順書（はじめての設定と、毎週・定期の作業）

- 初回の所要時間: 合計およそ2時間（A〜E）。以後は毎週30分と、50日ごとに15分
- **A から順番に**進めてください。前の段が終わらないと動かないものがあります
- Meta・Substack・Typeless の画面の名前は変わることがあります。見つからないときは各サービスの公式ヘルプで確認してください
- 鍵（アクセストークン・パスワード）は **GitHub の Secrets にだけ**置きます。チャット（Claude を含む）・Issue・メモには貼らないでください

| 段 | やること | 目安 | 終わりの目印 |
|---|---|---|---|
| A | ブランチを master に取り込む／PC のフォルダを最新にする | 15分 | Actions タブに SNS のワークフローが並ぶ |
| B | Threads の鍵を作って登録する | 30〜40分 | 疎通確認が ✅ |
| C | Substack を開設し、Threads から案内する | 20〜30分 | 固定投稿から登録できる |
| D | 試運転（下書き→承認→ドライラン） | 15分 | ログに投稿予定の文面が出る |
| E | 本番開始 | 5分 | 20:17 に1本目が出る |
| F | 毎週（日曜） | 30分 | 7本承認・メルマガ送信 |
| G | 定期（50日ごと・警報が来たとき・4週後） | 15分〜 | — |
| H | 決めておくこと | — | DECISIONS.md に記入 |

## A. 取り込む（15分）

### A-1. ブランチを master に取り込む（スマホのブラウザでも可）
自動化の仕組み（Issueフォーム・ワークフロー）は、master にあるときだけ動きます。

- **方法1（おすすめ）**: Claude に「プルリクエストを作って」と頼む → 届いたリンクを開く → 「Merge pull request」→「Confirm merge」
- **方法2（自分で）**:
  1. https://github.com/tamehiro3/tamehiro3.github.io を開く
  2. 「Pull requests」→「New pull request」
  3. base を `master`、compare を `claude/kind-davinci-qb2qpg` にする
  4. 「Create pull request」→ もう一度「Create pull request」
  5. 「Merge pull request」→「Confirm merge」

終わりの目印:
- 「Actions」タブに「SNS 受付」「SNS 定時投稿」「SNS 週次改善」「SNS テスト」「SNS Threadsの疎通確認」などが並ぶ
- 「Issues」→「New issue」に「SNS下書き」が出る

補足:
- 取り込んだ時点では `mode: dry-run` なので、何も投稿されません
- サイト（tamehiro3.github.io）の見た目は変わりません
- 他のブランチ（AdSense対策の `claude/pensive-shannon-…` など）と両方取り込んでも競合しないことを確認済みです

### A-2. PC の公開フォルダを最新にする（Windows）
「★サイトを公開する.bat」に「アップロードの前にサーバー側の更新を取り込む」処理を足しました。手元が古いままだと、本番開始後（ボットが記録をコミットし始めたあと）にアップロードが拒否されます。

1. サイトのフォルダを開き、エクスプローラーのアドレス欄に `powershell` と入力して Enter
2. `git pull origin master` を実行する
3. 以後は今までどおり「★サイトを公開する.bat」をダブルクリック。エラーが出なければ完了

「Your local changes would be overwritten」と出たら、手元に未公開の変更があります。先に .bat で公開してから、もう一度 2 を実行してください。

## B. Threads の鍵（30〜40分・PC のブラウザがおすすめ）

前提: Threads のアカウントと、Meta for Developers の登録（初回は電話番号などの確認を求められることがあります）。

### B-1. アプリを作る
1. https://developers.facebook.com/ → 右上「マイアプリ」→「アプリを作成」
2. アプリ名（例: `shinobi-sns`）を入れ、ユースケースで「Threads API にアクセス」を選んで作成

### B-2. 権限を付ける
3. アプリの画面 →「ユースケース」→ Threads API の「カスタマイズ」→ 権限に `threads_basic` と `threads_content_publish` を追加

### B-3. 自分をテスターにする（アプリ審査は申請しない）
4. 「アプリの役割」→「役割」→「メンバーを追加」→「Threadsテスター」→ 自分の Threads のユーザー名
5. スマホの Threads アプリ → 設定 → アカウント → ウェブサイトのアクセス許可 → 招待 → 承認

### B-4. 鍵（アクセストークン）を作る
6. ユースケース → Threads API → 設定の「ユーザートークン生成ツール」→ 自分のアカウントの「アクセストークンを生成」→ ログインして許可 → 表示された鍵をコピー
7. 鍵の期限が **60日（長期）** か確かめる。1時間（短期）だった場合は、公式ドキュメントの「長期アクセストークン」の手順で交換する（アプリシークレットを使います。シークレットも誰にも見せない）

### B-5. GitHub に登録する
8. PC のブラウザで https://github.com/tamehiro3/tamehiro3.github.io/settings/secrets/actions を開く（Settings → Secrets and variables → Actions）
9. 「New repository secret」→ Name: `THREADS_ACCESS_TOKEN`、Secret: 鍵を貼る →「Add secret」

`THREADS_USER_ID` は登録しなくても動きます。鍵をどこかに貼ってしまったときは、B-4 からやり直して上書きしてください。

### B-6. 鍵を作った日を書く
10. リポジトリで `_marketing/sns/config.json` を開き、鉛筆（Edit）を押す
11. `"token_issued_on": null,` を `"token_issued_on": "2026-09-27",` のように**鍵を作った日**に書き換える（ダブルクォートとカンマを消さない）
12. 「Commit changes」→ もう一度「Commit changes」
13. 1分ほどで Actions の「SNS テスト」が緑になれば OK。赤なら書き方の誤り（カンマ・引用符）を直す

### B-7. 疎通確認（投稿はされません）
14. Actions →「SNS Threadsの疎通確認」→「Run workflow」→ Branch は master のまま →「Run workflow」
15. 実行結果を開き、「✅ Threadsの鍵は使えます（@あなたの名前 …）」と「期限まであと60日」が出れば完了

❌ のときに多い原因: 鍵のコピー漏れ、B-3 の招待の承認忘れ、B-2 の権限不足。

## C. Substack（受け皿）（20〜30分）

### C-1. 開設する
1. https://substack.com でアカウントを作り、出版物（Publication）を作る
   - 名前: 週刊しのびの謎
   - URL: 例 `shinobi-nazo.substack.com`
   - 無料購読のみ（有料は設定しない）
2. 紹介文は事実台帳（`_marketing/OFFER_FACTS.md`）の範囲で。例:「毎週日曜、今日の謎と答え合わせが届く無料のメルマガです」

### C-2. 設定に入れる
3. `_marketing/sns/config.json` を編集する
   - `"links"` の `"メルマガ": ""` → `"メルマガ": "https://（あなたのURL）.substack.com/"`
   - `"newsletter"` の `"substack_url": null` → `"substack_url": "https://（あなたのURL）.substack.com/"`
4. Commit し、「SNS テスト」が緑になるのを確認

### C-3. Threads から受け皿へ橋を架ける（手作業）
5. Threads アプリ → プロフィール →「プロフィールを編集」→ リンクにメルマガの URL
6. 固定投稿を1本、手で投稿する。例文（機械検品を通過済み）:
   > 謎の答え合わせは、毎週日曜の週刊メルマガ「週刊しのびの謎」で。登録はプロフィールのリンクから。無料で読めます。
7. その投稿の「…」→「プロフィールに固定」

### C-4. 表示義務（特定電子メール法）
8. Substack の設定で、差出人名と、メールの末尾に載る情報を確かめる
9. 住所の載せ方を専門家に確かめ（H-1）、決まったら `config.json` の `"newsletter"` → `"address"` に書く（住所、または住所を載せたページの URL）。決まるまでは、下書きに「［住所…］」の空欄が出ます

## D. 試運転（15分）

### D-1. テキストの下書き
1. Issues →「New issue」→「SNS下書き」
2. 「投稿文」を Typeless で話す（例: 今日の謎を1問）。ジャンルとリンク先を選んで「Submit new issue」
3. 1分ほどで「軍配 機械検品レポート」がコメントされる（初回はこのとき、ラベル「SNS下書き」「承認」などが自動で作られます）
4. ❌ があれば本文を直す（保存すると再検品）。⚠️ は自分の目で確かめる
5. 本文の「検品チェック」に印を付ける（画像なしなら「画像」は不要）
6. 右側の Labels で「承認」を付ける
7. 「在庫に入れました」とコメントされ、Issue が閉じれば成功

### D-2. ドライラン
8. Actions →「SNS 定時投稿」→「Run workflow」（「ドライラン」にチェックが入ったまま）
9. ログに「投稿予定」の文面、「Threadsの鍵の期限まであと…日」、「認証情報: すべて設定済み」が出れば準備完了

### D-3. 画像つき（任意）
- **自分で**: Canva で画像を **幅1440px の JPG か PNG** で書き出して保存 → 新しい「SNS下書き」の「添付画像」に貼る → 「画像の説明」に画像の中の文字を全部読み上げる → 検品コメントに画像の大きさと文字認識の結果が出るか確かめる
- **Claude に頼む**: Canva と GitHub をつないだセッションで「今日の謎カードを作って下書きにして。謎は〇〇、投稿文は〇〇」→ プレビューに OK を出す → Claude が下書き Issue を作る（**承認はあなた**）

## E. 本番開始（5分）

1. `config.json` の `"mode": "dry-run"` を `"mode": "live"` に書き換えて Commit
2. `_marketing/ledgers/DECISIONS.md` の表の最後に1行足す:
   `| 2026-09-xx | 本番開始 | mode を live に | tamehiro3 | 決定 | 試運転で問題なし |`
3. その日の 20:17（日本時間）に在庫から1本投稿されます。すぐ試すなら「SNS 定時投稿」を**ドライランのチェックを外して**実行
4. Threads で投稿を確かめる。1本目はテキストだけの投稿がおすすめ

すぐ止めたいときは `"mode": "paused"` にして Commit。

## F. 毎週やること（日曜・30分）

1. **投稿を7本話す**: 輪番表（`BLUEPRINT.md` §4.2）を見ながら月曜の分から順に → 検品 → 印 → 承認
2. **週次改善**（21:07 に Issue が届く）
   - 「2.」に数字を写す: Threads のインサイト（インプレッション・いいね・返信・フォロワー数）と、Substack の購読者数
   - 「3.」に所見を一言、「4.」に提案があれば書く
   - 「5.」で裁定し、`DECISIONS.md` に1行足して Issue を閉じる
3. **週刊メルマガ**（同じ Issue の「6.」）
   - 下書きを開き、「あなたの一言」と「答え」を書く（Typeless で話して貼る）
   - Substack で新しい投稿を作って貼り、送信する
   - 下書きの下の「送る前のチェック」に印を付ける
   - 数字・効果の断言・「広告なし」などは書かない（事実台帳の範囲で）

## G. 定期・警報が来たとき

| いつ | やること |
|---|---|
| `[SNS警報] Threadsの鍵` が来たら（鍵を作って約50日後） | B-4 で鍵を作り直す → Secrets の `THREADS_ACCESS_TOKEN` を開いて「Update secret」で上書き → B-6 の日付を更新 → B-7 の疎通確認 |
| `[SNS在庫]` が来たら | 在庫が7本を切った。下書きを補充する |
| その他の警報 | `README.md` の「警報 Issue が来たら」の表を見る |
| 4週後 | 続ける・変える・やめるを裁定。Facebook ページを始めるかもここで決める |

鍵の期限が切れると、投稿は止まります（壊れた投稿は出ません）。

## H. 決めておくこと（決めなければ初期値のまま動きます）

| 事項 | 初期値 | 決め方 |
|---|---|---|
| H-1 メルマガの住所表示（特定電子メール法） | 空欄 | 専門家に確認。質問の例:「個人で無料メルマガ（自作ゲームの紹介を含む）を送る。住所は本文に必要か、住所を載せたページへのリンクで足りるか、バーチャルオフィスの住所でよいか」。総務省・消費者庁のガイドラインを読んだうえで、弁護士（自治体や法テラスの無料法律相談など）に |
| H-2 投稿時刻 | 毎日 20:17 | 変えたいときは Claude に頼む |
| H-3 公開リポジトリのままでよいか | 公開 | 画像つき投稿は公開リポジトリが前提。非公開にするなら画像の置き場を別に用意する |
| H-4 Threads の画像の代替テキスト | オフ | 最初の画像つき投稿のあとで試すか決める |
| H-5 表現ルール（`rules.json`） | 初版 | 足したい・外したい表現があれば Claude に |
| H-6 Canva テンプレート「今日の謎カード」 | これを使う | デザインを変えたければ Canva で作り直す |
| H-7 サイトにメルマガの登録リンクを載せるか | 載せない | 載せるなら `privacy.html` の更新が必要 |
