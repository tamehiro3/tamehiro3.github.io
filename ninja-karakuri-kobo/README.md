# ニンジャからくり工房（試作版）

30〜90秒の忍者試験を遊んで、作って、友だちの攻略で完成させるアスレチック・パズルです。
プレイヤーは見習いの試験職人。CryptoNinja の忍者39体が試験官になり、1人1本ずつ運営の試験（全39本）を担当します。

- 遊ぶ: https://tamehiro3.github.io/ninja-karakuri-kobo/
- 遊び方・保護者の方へ: `about.html`
- キャラクターシート（39体）: `sheets/`

CryptoNinja（CC0・Ninja DAO）のキャラクターを使った個人制作の非公式ファンゲームです。試験官のひとこと・工房での役・担当の試験はゲームの創作です。ユーザーが作った試験は「ユーザー作品」として運営の試験と分けて表示します。

## 動かし方

ライブラリなしの HTML / JavaScript だけで動きます（ビルド不要）。

```sh
# リポジトリの直下で
python3 -m http.server 8765
# → http://127.0.0.1:8765/ninja-karakuri-kobo/
```

オフライン用の Service Worker は http(s) のときだけ動きます。

## テスト

```sh
node ninja-karakuri-kobo/tools/test_rules.mjs     # 結果: 159 件合格 / 0 件不合格
node ninja-karakuri-kobo/tools/solve_stages.mjs   # 運営の試験39本＋見本6本がクリアできるか（数分かかる）
```

`test_rules.mjs` で確かめること：

- 運営の試験39本と見本6本が、記録した入力の再生でクリアできる（内容のハッシュとコマ数も一致）
- 失敗すると0.5秒で直近のチェックポイントに戻る（残機なし）。120秒で時間切れ
- §13-1 未接続の扉・スイッチ、埋まったゴール、部品80・仕掛け10・チェックポイント2 の超過を検出。修正必要の版は申請できない
- §13-2 作者クリアは入力の再生で確かめ、編集すると消える（元の形に戻してもテストし直し）。ルールの版がちがうクリアでは申請できない
- §13-3 一覧や版のデータがこわれても `.bak` から戻る。自動保存の履歴（12件）から前の状態に戻せる。書きこめないときは黙って消さない
- §13-4 形のこわれたデータ・知らない項目や部品・はみ出し・大きすぎるデータは不合格。他人の owner_id の作品は書き換え・申請できない。申請後にすり替えた版や、再生でクリアにならない版は承認しない。こわれた・クリアできない記録つきの試験コードは読みこまない
- §13-5 AI の提案に未知の部品・座標外・コードのような文字列・知らない項目・入れ子の値があれば使わない。検査しただけでは試験は変わらない。定型の提案は6種の仕掛けすべてで検証に通る案を出す。1日3回・12秒
- §13-6 通報でその端末の表示を止め、確認して戻す／停止のまま（数だけで消さない）。作者の非表示。非公開 → 再申請。新しい版 → 申請の取り消し → 差戻し（理由と直す場所）→ 直して承認 → 前の版は旧版に
- §8 公開枠3本（非公開にすると空く）・§13-7 下書き枠：拡張がなくなっても既存の下書きは読めて編集でき、新規作成だけを止める（勝手に消さない）。復元でまた作れる
- §9 修行印は運営の試験の合格・目標タイム以内・週のお題でだけ増える（作品を作る・周回するだけでは増えない）
- §7 攻略メモの受け渡しと、改善の提案（挑戦12回・2人以上から。「2番目の予告付き罠で失敗が集中」）
- §11 試験コードで内容のハッシュが変わらない。ハッシュは部品の並び順や ID に左右されない
- §13 のイベント12種を記録している

## 試験を作り直す・足すとき

`stages.js` を変えたら、解答機で確かめて `solutions.js` を書き直します（お手本と目標タイムが変わります）。

```sh
node ninja-karakuri-kobo/tools/solve_stages.mjs 12 13      # 番号を指定して確かめる
node ninja-karakuri-kobo/tools/solve_stages.mjs --write    # 全部を確かめて solutions.js を書き出す
```

`data.js` の物理の数値を変えたら `VERSION.rules` を上げます（作者クリアと記録はルールの版ごとに分かれます）。

## キャラクターシートを作り直す

`art.js` / `chars.js` / `sheet.js` を変えたら画像を作り直します。Chromium と playwright、フォント（TTF。名前の筆文字は Yuji Boku、見出しは Zen Kaku Gothic New 700/900、絵の中の小さな字は Zen Maru Gothic。どれも Google Fonts・SIL OFL）を使います。
シートの原型（CC0）は、ニンジャ相棒道場と同じものを使います。公式イラストは `ninja-aibou-dojo/img/official/<id>.jpg`（高画質化したもの。なければ `img/art/<id>.jpg`。置き場所は `OFFICIAL_ART` で変えられます）、全身の公式3Dフィギュアは `ninja-aibou-dojo/img/official/fig/<id>.jpg`（`OFFICIAL_FIG` で変えられます）。「見た目のポイント」と顔のアップの範囲も `ninja-aibou-dojo/chars.js`（`LOOK`・`faceBox`）から読みます。作り方は `ninja-aibou-dojo/README.md` の「キャラクターシート・アイコンを作り直す」を見てください。

```sh
CHROME=/path/to/chrome SHEET_FONT_DIR=/path/to/fonts node ninja-karakuri-kobo/tools/build_sheets.mjs
```

## 更新するとき

- 中身を変えたら `index.html` の `?v=2` と `sw.js` の `CACHE` / `V` の番号を上げる（上げないと、ホーム画面に追加した人に古い版が残る）

## 設計書との対応

| 設計書 | この試作版 |
|---|---|
| §1・§2 遊ぶ人／作る人／運営 | 遊ぶ（運営の試験39本・友だちの試験）、作る（工房）、運営（審査と通報の確認の画面。設定で表示） |
| §3 最初の10分 | 案内つき：見本2本 → 罠の試験で失敗と即再開 → 見本の1か所を編集 → 提案で仕掛けを1つ → 作者クリアして下書き保存。「遊ぶだけにする」も選べる |
| §4 2.5D・32×12・120秒・チェックポイント2・部品80・仕掛け10・残機なし・1操作で再開 | すべてある。スマホは ◀ ▶・ジャンプ・術のボタン、パソコンはキーボード |
| §5 部品10種・水渡りの術1つ | すべてある。任意スクリプト・外部画像・外部音声は入れられない |
| §6 状態の流れ・version_id・公開中の版を書き換えない | ある。新しい版で作者クリアと審査をやり直す。記録は版（内容のハッシュ）に結びつく |
| §7 AI（選択式・JSON・検査・1日3回・12秒・失敗は数えない・十分な試行がなければ提案しない） | 標準は定型の提案（ルールで作る案）。AI は設定で接続先（https）を入れたときだけ使う試験機能。改善の提案は攻略メモから |
| §8 カタログ・定型リアクション・定型の作品名・公開枠3・下書き10・審査・通報3種・作者非表示 | すべてある。審査は試作版では端末の中の自動審査（切りかえると運営画面で手で審査） |
| §9 外見テーマ3つ・修行印 | 竹林・屋敷・天空道場（見た目だけ）。修行印で装束・演出・看板の飾りと交換 |
| §10 課金 | 入れていない（現実のお金の購入・広告の報酬なし。プレイ画面に広告のコードを入れていない） |
| §11 データ・ハッシュ・検査・自動保存・自己ベスト | ある。記録は自己ベストのみ（ランキングなし） |
| §13 受け入れテストとイベント | `tools/test_rules.mjs`。イベントは端末の中だけで数える（記録 → 試作の計測。JSON で書き出せる） |
| サーバー・オンラインの公開カタログ | 試作版にはない。友だちとは「試験コード」「攻略メモ」の文字で交換する。公開・通報・審査は端末の中で完結 |
| Roblox 版・購入の復元 | 入れていない（ブラウザ版の試作）。下書き枠の拡張・復元は受け入れテストで扱いだけを確かめている |
