## 2. 作り直した設計図

```
[クラウド（Claude）]                              [ためひろさんの Windows PC]
 台本・図解の設計 → 仮の声で試作 → 機械検品        キー: C:\Users\3mori\SNS\fal APIキー.txt（リポジトリの外）
          │ git push（作業ブランチ）                声: Obsidian の m4a（リポジトリの外。パスで指定）
          ▼                                                  │
 ────────────── git pull ─────────────────────────────────▶ │
                                                   ① python tools/setup.py        … 環境（何度実行しても安全）
                                                   ② python tools/fal_api.py check     … キーが読めるか
                                                   ③ python tools/fal_api.py selftest  … 接続・API仕様の確認（既製の声で1語）
                                                   ④ clone → tts（試しの1文）→ 本人が試聴
                                                   ⑤ python tools/fal_api.py approve   … 【承認ゲート】ここを通らないと先に進まない
                                                   ⑥ tts.py --engine fal → render.py → qa.py（Whisper 照合つき）
                                                   ⑦ 出荷判定（gunbai_review.md）→ 本人が手動で投稿
```

変えたこと：

1. **どの OS でも動く**
   - `tools/setup.py`（Python製）に一本化した。Linux 用の `setup.sh` は、仮の声を apt で入れてから setup.py を呼ぶだけにした。
   - フォントは OS に頼らず `assets/fonts` に取得する（M PLUS Rounded 1c の Black と Bold）。
   - 絵文字は画像にして `assets/emoji` に同梱した（30個）。
   - 単語の区切りは、辞書を同梱した純 Python の Janome にした（MeCab のインストール不要）。
   - Open JTalk がない環境でも、テロップの切り替え時刻は文字数の比率で決め、そのあと無音の位置に合わせる。
   - ffmpeg の結合リストのパスは Windows 形式に対応した。
2. **秘密と声はリポジトリの外**
   - キーは、リポジトリの1つ上のフォルダ（`fal APIキー.txt` / `.fal_key` / `.fal_key.txt`）か `_shorts/assets/.fal_key` から読む。
   - ルートの `.gitignore` で、キーらしい名前（`*キー*`・`.fal_key*`・`.env` など）を除外した。
   - 声の素材はパスで指定し、リポジトリにコピーしない。
3. **穴を穴として扱う**
   - fal の経路は「未検証」と明記した。
   - 最初に `selftest` で、キー・接続・入力項目名をまとめて確かめる。
4. **承認ゲート（fail closed）**
   - `approve` を実行するまで、`tts.py --engine fal` は止まる。
   - 本人の声かどうかを決めるのは本人。
5. **工程順**
   - 声の関門（③〜⑤）を、全文の生成と動画の作り直しより前に置いた。
   - 仮の声の動画は「構成とテンポの確認用」と位置づける。
