# SNS別ターゲット設計図を作る

SNSは場ごとに「開く理由」が違う。同じ商品でも、X では議論の中で、Instagram では憧れの中で、YouTube では検索の答えとして出会う。だから設計図は「全SNS共通のペルソナ1枚」ではなく、**SNSごとに、誰の・どの欲望に・何を・どのレバーで売り、売上の方程式のどの因数を担当させるか**を1枚ずつ書く。

このスキルの材料は4つ。中身は `references/` にある。

| 材料 | 何に使うか | ファイル |
|---|---|---|
| お金を払いたくなる6分野・人がお金を払う13の欲望 | 誰が、何の痛みを消すために払うのか | `references/desires.md` |
| 売上の方程式（見込み顧客数×購入率×購入単価） | 各SNSに担当させる因数と、見る数字 | `references/levers.md` §1 |
| 貧乏向けの5つ／富裕層向けの5つの売り方 | 同じ欲望でも客層で変わる言い方 | `references/levers.md` §2〜4 |
| 7つのSNSの性質と、欲望との相性表 | どの場でどの欲望が動くか | `references/platforms.md` |

## 手順

### 0. 前提を集める（先に手元を読む）

リポジトリやフォルダに事業の資料があれば、ユーザーに聞く前に読む。特に:
- 事実台帳（例: `OFFER_FACTS.md`）… 設計図に書いてよい事実はここにあるものだけ
- 禁止表現の一覧（例: `rules.json`）… 設計図の「見せるもの」が禁止表現を前提にしていないか照合する
- 判断ログ（例: `DECISIONS.md`）… すでに決まった主戦場・受け皿・予算をひっくり返さない。変える提案は「本人判断事項」に回す

足りなければ聞く。聞くのは次の5つまで（全部そろわなくても、仮置きを明記して進める）:
1. 何を売っているか（無料・広告収益も含む）と価格
2. いま誰が買っている／使っているか（実在の声があれば）
3. 売上の実績と、計測できている数字
4. すでに使っているSNSと、使える時間（毎日何分・週何本）
5. 絶対にやりたくないこと

事業がまだ決まっていない、または「一般論として」と頼まれたら、**汎用版**（13欲望×7SNSの相性表と、SNSごとの定石）を `references/platforms.md` から組み立てて出す。事業版の手順1〜7は飛ばしてよい。

### 1. 欲望を診断する（`references/desires.md`）

- **払う人と使う人を分ける。** 子ども向けなら払う・選ぶのは親、介護なら子世代のことがある。SNSで話しかける相手は「払う人」。
- **本音と建前を1つずつ決める。** 本音は消したい痛み（13欲望のどれか）、建前は人に説明できる理由。本音は言葉にすると反発を招くことがある（性欲・ラク・一発逆転など）ので、**本音は場面で見せ、建前を言葉にする**。
- 主欲望は1つ、副は2つまで。欲張ると旗（何の人か）がぶれる。
- **除外する欲望を理由つきで書く。** 「この欲望には刺さるが、旗や信用とぶつかるので使わない」という判断が、設計図のいちばん価値のある部分になることが多い。

### 2. 客層とレバーを決める（`references/levers.md`）

- 客層は「貧乏（価格と即効性に敏感）」か「富裕層（時間と確実さにお金を払う）」か。同じ欲望でも客層で売り方が変わる。
- 10のレバーを1つずつ「使う／条件つき／使わない」で判定し、理由を書く。使えないレバーを無理に使うと、そこが誇大表示になる（例: 無料商品の「期間限定」、実績のない「権威」）。
- 入口は貧乏レバー、本命は富裕レバー、が基本形。**1つのメッセージに両方を混ぜない。**

### 3. 売上の方程式に分解する（`references/levers.md` §1）

- 見込み顧客数・購入率・購入単価のそれぞれについて、この事業での読み替え（広告収益・無料なら何に当たるか）、いまの状態、担当するSNS、見る数字を表にする。
- 掛け算なので、**いちばん弱い因数から直す**。ゼロの因数があれば、そこ以外を磨いても売上はゼロ。
- 実数がないなら空欄と「未計測」でよい。**数字を作らない。** 例示の数字を書くなら「仮の数字」と明記する。

### 4. SNSごとに1枚ずつ書く（`references/platforms.md`）

X・Instagram・TikTok・YouTube・Substack・note・Brain の7枚を、`assets/template.md` の「SNSカード」の形で書く。ユーザーがすでに一覧外のSNS（Threads など）を主戦場にしているなら、それも1枚目に足す。

- ペルソナは年齢・性別の属性ではなく「どんな状況で、どんな変化を望んでいる人か」で書く。実在の顧客の声がまだなければ「仮説」と書く。
- 相性の悪いSNSは、無理に埋めずに「×（使わない）」と理由を書く。7枚すべてを◎にした設計図は、どれも選んでいないのと同じ。
- 規約・仕様（リンクの扱い、子ども向け設定、成人向けの扱いなど）は変わる。`references/platforms.md` は定性的な出発点なので、断定せず「要確認」を付け、確認した日付と出典があれば書く。

### 5. 優先順位を付ける（一点張り）

- 同時に本気で回すのは**主戦場1つ＋受け皿（メールなど自分のリスト）1つ**まで。7つ全部を薄く回すより、1つを毎日のほうが強い。
- 2つ目以降は「いつ・何が起きたら足すか」の条件で並べる（例: 主戦場の4週の裁定で続けると決まったら）。
- 順位の根拠が調査でなければ「勘」と書く。勘は悪くない。勘を調査に見せかけるのが悪い。

### 6. 検品する

出す前に、設計図そのものを点検する。
- **事実**: 書いた実績・数字・特徴が、すべて事実台帳（なければユーザーの発言）にあるか。
- **表現**: 「見せるもの」の例文が、効果の断言・No.1・実態のない希少性・収入の断言・公式の誤認になっていないか。禁止表現の一覧があれば照合する。
- **法と規約**: 欲望ごとの地雷（`references/desires.md` の最終列）と、SNSごとの禁止線に触れていないか。この検品は適法性の保証ではなく事前の選別なので、微妙なものは「要専門家確認」とする。
- **弱い立場の人**: 一発逆転・健康・美容・教育は、困っている人ほど強く反応する市場。煽りの強さで売上を取りにいく設計になっていないか（`references/desires.md` §4）。

### 7. 本人判断事項を分けて書く

商品・価格・販路・主戦場の変更、予算、やらないことの解除は、**設計図の中で決めない**。選択肢と理由までを書き、「本人判断事項」として最後にまとめる。判断ログがあるリポジトリなら、ログに「本人判断待ち」の1行を足す（ログは追記のみで、既存の行は書き換えない）。

## 出力

- 形は `assets/template.md` に従う（0〜9節＋SNSカード）。表を多めに、1セルは短く。
- 置き場所は、事業の資料がまとまっているフォルダ（例: `_marketing/TARGET_MAP.md`）。なければユーザーに聞くか、作業フォルダに置いて場所を伝える。
- 最後にユーザーへ伝えるのは3つだけ: 結論（主戦場・次の候補・使わないSNS）、本人判断事項、設計図の場所。

## 軍配（pro-marketing-director）と一緒に使うとき

軍配が使える環境なら、設計図は軍配の「戦略盤面（positioning）」の下に置く。フェーズ判定（P0〜P2）で装備の量を決め、SNSを足す提案は戦略宣言、投稿の方針はKPI宣言の形で書き、検品は軍配の4検品に合わせる。軍配がなくても、このスキルだけで設計図は完結する。
