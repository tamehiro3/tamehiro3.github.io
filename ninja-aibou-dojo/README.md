# ニンジャ相棒道場（試作版）

教えたことを覚えて、一緒に強くなる相棒。相棒育成＋短い修行アクションです（設計書「③ ニンジャ相棒道場：詳細設計書 v1.0」のブラウザ版試作）。
プレイヤーは見習い忍者で、ゲーム独自の相棒と修行します。師匠として課題を出すのは CryptoNinja の忍者39体です。

- 遊ぶ: https://tamehiro3.github.io/ninja-aibou-dojo/
- 遊び方・保護者の方へ: `about.html`
- キャラクターシート（道場版・39体＋相棒）: `sheets/`

CryptoNinja（CC0・Ninja DAO）のキャラクターを使った個人制作の非公式ファンゲームです。相棒はこのゲーム独自のキャラクターで、セリフ・師匠としての設定はゲームの創作です。
同じサイトの「ニンジャ里ライフ」（`../ninja-sato-life/`）とは別のゲームで、ファイルも独立しています（どちらかを消しても、もう一方は動きます）。

## 動かし方

ライブラリなしの HTML / JavaScript だけで動きます（ビルド不要）。

```sh
# リポジトリの直下で
python3 -m http.server 8765
# → http://127.0.0.1:8765/ninja-aibou-dojo/
```

`file://` で開いても遊べますが、オフライン用の Service Worker は https のときだけ動きます。

## テスト

```sh
node ninja-aibou-dojo/tools/test_rules.mjs   # 結果: 114 件合格 / 0 件不合格
```

§12 の7項目（同じ seed・方針で同じ判断を再現／「救助を優先」後に救助を選ぶ／危ない救助を避けたときの説明が実際のルールと一致／直前の指導を戻すと以前の方針／不可能・矛盾・不適切な入力を保存しない／日記は承認済みの出来事だけ・AIなしで全5章を最後まで（練習設定なら成功、なしでも結果まで進む）／引き継ぎ・二端末の競合・見た目の権利）と、代表的な日本語の指示43件での意図の一致（目標95%以上）、最初の10分の因果確認、どの方針でも3種の修行を完走できること、39体のデータ・セリフ・絵を確かめます。

## キャラクターシート・アイコンを作り直す

`art.js` / `chars.js` / `sheet.js` を変えたら作り直します。Chromium と playwright-core、フォント（TTF。名前の筆文字は Yuji Boku、見出しは Zen Kaku Gothic New 700/900、小物の字は Zen Maru Gothic。どれも Google Fonts・SIL OFL）を使います。
シートの原型（公式イラスト・CC0）は `img/official/<id>.jpg` を読みこんで画像の中に入れます（なければ `ninja-sato-life/img/art/<id>.jpg`。置き場所は `OFFICIAL_ART` で変えられます）。
全身の公式3Dフィギュアは `img/official/fig/<id>.jpg` を入れます（置き場所は `OFFICIAL_FIG` で変えられます。ないときは、その場所に「ゲームの中の姿（まえ）」を描きます）。
`img/official/` は `tools/upscale_official.py` で作ります（`pip install ncnn numpy opencv-python-headless`。モデルは [Real-ESRGAN のリリース](https://github.com/xinntao/Real-ESRGAN/releases) の `realesrgan-ncnn-vulkan-*.zip` の `models/` を `REALESRGAN_MODELS` で指定）。
`img/official/fig/` は `tools/extract_official_figures.py` で作ります（`NINSAI_SHEETS` に ninsai-kakurenbo の `img/sheets` の場所、モデルは同じリリースの `realesrgan-x4plus`）。ninja-dao.com から元の大きな画像を取れるときは、そちらを `OFFICIAL_FIG` に置くほうが、よりくっきりします。
`SHEET_STYLE=cool` を付けるとかっこいい版（約5頭身）、`SHEET_STYLE=cute` を付けるとかわいい版（ちびキャラ）で作ります。

```sh
PLAYWRIGHT_CORE=/path/to/node_modules/playwright-core \
CHROME=/path/to/chrome \
SHEET_FONT_DIR=/path/to/fonts \
node ninja-aibou-dojo/tools/build_sheets.mjs        # 全員（相棒の見本は partner）
node ninja-aibou-dojo/tools/build_sheet_index.mjs   # 一覧ページ
PLAYWRIGHT_CORE=... CHROME=... node ninja-aibou-dojo/tools/build_icons.mjs
```

## 設計書との対応

| 設計書 | この試作版 |
|---|---|
| §1 相棒1体・師匠は CryptoNinja・公式キャラの性格を書き換えない | 相棒はゲーム独自（外見と呼び名を選ぶ）。39体は師匠（日替わり）・救助役・護衛役として登場 |
| §2 コアループ・1回3〜5分・罰なし | 作戦 → 修行 → 相棒が判断 → 代表場面を振り返る → ほめる／教える → 次の修行で確認。毎日の世話や不機嫌・弱体化はない |
| §3 最初の10分 | 相棒づくり → 短い道（指示を試す）→ 見守りタイム（宝箱と倒れた仲間）→ 教える（前後の方針を表示）→ 配置を変えた似た課題 → 小ボス → 師匠の評価・記念写真 → 次に教えたいこと。最初の因果確認は配置と立ち位置を固定し、教えた結果を必ず確かめられる |
| §4.1 方針3軸・行動5候補・除外・優先ルール | ある。救助スコア＝緊急度＋支援優先補正−危険補正、探索スコア＝価値＋探索優先補正−味方危機補正 など（`policy.js`）。直接指示と、体力がわずかな時の退避は優先ルール |
| §4.2 教える仕組み | 振り返りで代表2件・「この行動を続ける／次は〜／安全を優先」・各軸±10・即表示・確定で反映。作戦は3枠で数値より優先。履歴・直前の取り消し・全リセットは無料 |
| §5 修行3種・3場面＋実戦・HP100・3秒救助・全滅しても失わない・練習設定 | ある。1つの道場を seed で配置替え |
| §5 成長（経験・道場札・絆・作戦プリセット） | 成功30／失敗15・Lv1〜10（Lv2まで60）。道場札で見た目（衣装100 など）。絆は指導と共同達成（購入不可）。作戦の枠は物語で3つまで（救助型・探索型・護衛型） |
| §6 外見・傾向カード・5章・写真 | 衣装・木刀・道場の壁／床／置物・登場ポーズ。「救助が得意」などの傾向カード。5章。写真は選んだ呼び名と記録だけ |
| §7 画面・操作 | 道場・作戦・修行・振り返り・回想。斜め上のカメラ・自動の通常攻撃・移動／回避／指示は手動。3軸はアイコンと短文で説明 |
| §7 オフライン | 標準修行・指導・物語・定型の振り返りと日記はオフラインで動く |
| §8 言葉を作戦にする（AI試作） | 端末の中のルールで読み取り（入力検査→意図→許可ルールと範囲の検証→変更案→確定）。設定でAIの接続先（https）を入れたときだけ送る。1日5回・日記1日1回・8秒で端末の読み取りへ。あいまい→選択肢、不可能→実装できる作戦を提案。日記は出来事IDを検査 |
| §9 課金 | 入れていない（サイトの方針：課金・ガチャ・スタミナなし、遊ぶ画面に広告なし）。見た目は道場札でだけ交換 |
| §10 データと再現性 | Companion・PolicyState（version）・LessonEvent（policy_version・scenario_seed・候補と点数）・MemorySummary（承認済みの出来事ID）・ChapterProgress・Entitlement。同じ場面の前回と違う行動は、方針の差といっしょに振り返りで表示 |
| §10 二端末・購入の復元 | 引き継ぎコード（通信なし）。競合したら選ぶ画面（数値をまぜない）・選ばなかった記録は7日保管。見た目の権利は進行と別に合わせる |
| §12 受け入れテスト・イベント | `tools/test_rules.mjs`。instruction_proposed/confirmed・behavior_changed・lesson_complete・policy_undo・memory_view・chapter_complete を端末の中だけで記録（メニューから書き出し） |
| Roblox 版・合同修行・サーバー | 入れていない（ブラウザ版の試作） |
